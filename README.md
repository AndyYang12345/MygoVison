##### 任务二：相机图传
###### 打开MaixVison
本项目使用了硒速科技的最新相机模块MaixCam2，有出色的硬件性能，运行着Linux系统，并针对部分OpenCV算法进行了硬件上的优化。他们开发的MaixPy（基于python）是专门用于进行视觉开发的，大大降低了上手门槛，并且提供了简易的MaixCDK用于底层API开发。在本视觉项目中，我打算利用这个优秀的平台，基于OpenCV在C++的高性能实现和其提供的MaixCDK进行底层识别算法的交叉编译，生成供MaixPy运用的API接口，用富有逻辑性的Python语言实现后续业务逻辑开发。现在展示的是MaixCam官方IDE，用于简单的视觉项目调试以及与视觉模块的远程连接。

#### 核心技术点**高解耦度、识别算法、3D投影**
从底层开始构建仿真算法，从TargetSim类用于生成指定位置、指定旋转角度的标准靶子图片，到TrainingFrameGenerator类用于生成仿真流类，给定时间戳并根据当前旋转速度函数调用TargetSim对象生成对应状态的图片。从此便可以做出一个较为真实的仿真对象了。为了监视帧率等情况，我封装了PerformanceMonitor类，只需要在启动流类的时候初始化一下，并在生成帧的时候调用tick就可以自动统计当前帧率。

接着我开始实现最基本的识别算法，封装了一个TargetTracker类，只要初始化一个追踪器对象并向其传入相机捕获到的图像数据也就是Mat类型数据，就可以自动分析并得到目标色块的位置。

关于这个追踪算法的实现我也用过不同思路，就识别顺序这方面而言，我最开始采用的是直接获取整张图片上的所有色块信息并存储到数组中。将他们每个色块的位置进行比较，得到一个色块到其他色块的位置几乎一样的时候，那个色块就是中心色块。接着基于中心色块的颜色和周围色块颜色的相似度捕捉目标色块的位置信息。这个算法乍一看没有什么问题，但是将每个色块位置与其他色块位置进行比较及其繁琐，不用想都知道这个思路的效率绝对不合格。我又基于靶子的形状特征对色块和圆形的相似度进行比较，这样一来只用比较6遍就可以准确确定出中心色块的位置了。颜色相似度的分配方面我也遇到了不少问题，比如识别算法在出现黑色色块和其他深色色块的时候总是会误识别，相近颜色也会导致误识别。于是我引入了HSV色彩空间，后来又引入了LAB色彩空间，在中心颜色的不同取值下采用三种色彩空间相似度的不同权重获得最恰当的色彩相似度。

然后我又实现了仿真相机类的实现，并基于此实现了由平面仿真流到空间仿真流图像的投影，接着我应用厂家提供的相机内参进行了仿真相机的初始化，得到了映射在空间中的仿真图像。同样，为了解耦并抽象，我封装了PentagonSimulator类，只需要传入靶子位置、相机位置角度就可以获得实时的仿真图像。

该项目的解耦为后续API移植提供了可行的路径，后续还会应用官方接口优化我的代码逻辑，实现效率更高的识别。
